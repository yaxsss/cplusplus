# 六大特殊成员：手写 `{}` 和 `= default` 差在哪

对应代码：[`base/default_function.cpp`](../base/default_function.cpp)  
运行结果：[`base/result.txt`](../base/result.txt)

空类上让编译器自己生成、手写一个空函数、或写 `= default`，用 type trait 看「在不在」和「是否 trivial」。先记住两件事：

- **用户提供**（有函数体，哪怕 `{}`）→ 这个函数 **不是 trivial**，而且可能让别的特殊成员不再生成。
- **`= default`**（第一次声明就默认）→ 对空类仍是 trivial，但「声明了某个构造函数」这一条规则照样生效。

打印用的是 `is_*_constructible` 这类 trait，**不等于「类里真的声明了这个函数」**，下面 Case4 / Case6 会碰到。

---

## 编译器怎么生成（C++11）

| 成员 | 何时还会隐式声明 |
|------|------------------|
| 默认构造 | 没有声明**任何**构造函数 |
| 析构 | 没有声明析构 |
| 拷贝构造 / 拷贝赋值 | 没有声明自己；若声明了移动构造或移动赋值，则被 **delete** |
| 移动构造 / 移动赋值 | 拷贝构造、拷贝赋值、另一个移动、析构 **全都没声明** 才生成 |

手写空 `{}` 和 `= default` 都算「用户声明」，都会触发上表；差别只在 **trivial / POD**。

---

## trait 会说谎：能移动 ≠ 有移动构造

`is_move_constructible_v<T>` 的意思是 `T(T&&)` 能编译。没有移动构造时，**拷贝构造 `T(const T&)` 也能接住 `T&&`**，trait 照样是 `true`。

所以结果里「移动构造：存在 true」经常只是「可以拷贝」。要看是不是真合成了移动，得看 **平凡** 那一列：走的是非平凡拷贝，平凡就是 `false`；拷贝本身平凡，平凡就是 `true`。赋值同理。

---

## Case1：什么都不写（对照基线）

六个都在，全 trivial；聚合、标准布局、POD、Trivial 全是 true。后面每个 Case 都拿它当参照。

## Case2–8：各手写一个空函数体

### Case2 `Case2() {}`

默认构造 **在，但不平凡**。其余仍合成且平凡。  
有用户提供的构造函数 → 不是聚合；不 trivial → 不是 POD。

### Case3 `Case3(int) {}`

声明了构造函数 → **没有默认构造**。拷贝/移动/析构仍在。同样不是聚合、不是 POD。

### Case4 手写拷贝构造

- 有用户声明的构造函数 → **没有默认构造**。
- 拷贝构造在，不平凡。
- 按规则 **不会再合成移动构造**。结果里移动构造「存在 true、平凡 false」：走的是这份非平凡拷贝。
- 移动赋值「存在 true、平凡 true」：没合成移动赋值，走的是仍平凡的拷贝赋值。

### Case5 手写移动构造

声明移动构造 → 拷贝构造、拷贝赋值被 **delete**，也不会合成移动赋值。  
结果：只有移动构造（不平凡）和析构（平凡）。这是「只留下移动」的典型形状。

### Case6 手写拷贝赋值

赋值不是构造函数 → **默认构造还在**，而且平凡。拷贝构造仍合成。  
用户声明了拷贝赋值 → 不合成移动。移动相关 trait 为 true，是因为可以走拷贝；拷贝赋值不平凡，所以「移动赋值平凡 false」。

结果里 **仍是聚合**（没有用户提供的构造函数）。不 trivial → 不是 POD。

### Case7 手写移动赋值

声明移动赋值 → 拷贝构造/拷贝赋值被 delete，不合成移动构造。  
默认构造、析构仍在且平凡。没有用户声明的构造函数 → **仍是聚合**。

### Case8 手写析构 `~Case8() {}`

析构不平凡。关键：`is_trivially_*constructible` 要求 **析构也平凡**，所以默认构造、拷贝构造、移动构造的「平凡」全变成 false。  
赋值不经过析构，「拷贝/移动赋值平凡」仍是 true。  
用户声明析构 → 不合成移动；移动构造 trait 为 true 是靠拷贝。  
C++17 里用户提供析构 **仍可以是聚合**（结果是 true）。不 trivial → 不是 POD。

## Case9–14：对应的 `= default`

和 2–8 同一套「谁被声明了」的规则，但空类上这些函数 **可以是 trivial**。

| 和手写对比 | 手写 `{}` | `= default` |
|------------|-----------|-------------|
| Case2 vs 9 默认构造 | 默认构造不平凡；非聚合；非 POD | 全 trivial；聚合；**POD** |
| Case4 vs 10 拷贝构造 | 拷贝不平凡；移动 trait 靠拷贝（不平凡） | 拷贝平凡；移动 trait 靠平凡拷贝 → 移动也显示平凡。有用户声明的构造 → 无默认构造 → **不是 trivial/POD**（结果仍是聚合，C++17） |
| Case5 vs 11 移动构造 | 移动不平凡 | 移动平凡。拷贝仍被 delete。无默认构造 → 非 POD |
| Case6 vs 12 拷贝赋值 | 赋值不平凡 → 非 POD | 赋值平凡；走拷贝的移动 trait 也平凡 → **POD** |
| Case7 vs 13 移动赋值 | 赋值不平凡 → 非 POD | 赋值平凡；拷贝仍 delete。结果 **Trivial/POD 为 true**（平凡可复制靠平凡移动赋值 + 平凡析构，外加平凡默认构造） |
| Case8 vs 14 析构 | 析构不平凡，连累构造也不平凡 | 析构平凡，六个都平凡 → **POD** |

Case9 / 12 / 14 和 Case1 一样「看起来像空类」：`= default` 没有破坏 trivial。  
Case10 / 11 只是把某个构造函数写出来了，即使 `= default`，也 **没有默认构造**，所以不是 POD。

## Case15：`= default` 默认构造 + 删除拷贝

```cpp
class Case15 {
public:
    Case15() = default;
    Case15(const Case15&) = delete;
    Case15& operator=(const Case15&) = delete;
};
```

声明拷贝构造/拷贝赋值为 delete → 移动构造/移动赋值也不会再合成，拷贝和移动的 trait 全是 false。  
默认构造 `= default` → 仍在且平凡；析构仍隐式生成且平凡。

结果：**聚合 true、POD true、Trivial true**。

它回答了「默认构造会不会同时决定聚合和 POD」：

| | 要不要默认构造 | Case15 | 反例 |
|--|--|--|--|
| **POD / trivial** | **要，而且必须平凡** | 有 `() = default` → POD | Case10 只 default 了拷贝构造，没有默认构造 → 非 POD |
| **聚合（C++17）** | **不要**。只禁止用户**提供**的构造函数（有 `{}` 的那种） | `= default` / `= delete` 都不是 user-provided → 仍是聚合 | Case2 `() {}` 是 user-provided → 非聚合；Case10 没有默认构造，C++17 里 **仍是聚合** |

所以 **两者不是都受「有没有默认构造」左右**：

- 弄丢 **POD**：没有平凡默认构造（没写、或写了带参/拷贝/移动构造把默认构造挤掉、或默认构造是手写 `{}`）。
- 弄丢 **聚合（C++17）**：写出用户提供的构造函数（`Case2() {}`、`Case3(int)`）。缺默认构造本身不拆聚合；`= default` / `= delete` 也不拆。

C++20 起聚合改为「不能有用户**声明**的构造函数」，那时 Case9 / 10 / 11 / 15 都会不再是聚合。本结果是 C++17。

---

## 为什么 `= default` 的拷贝/移动构造会影响 POD，默认构造却不会

不是「拷贝/移动本身把 POD 弄坏了」，而是 **它们也是构造函数**：一写出来（哪怕 `= default`），编译器就不再给默认构造。POD / `is_trivial` 要求 **既平凡可复制，又有平凡的默认构造**。没有默认构造 → 不是 trivial → 不是 POD。

```text
Case9   Case9() = default;               默认构造还在且平凡 → POD
Case10  Case10(const Case10&) = default; 声明了构造函数 → 没有默认构造 → 非 POD
Case11  Case11(Case11&&) = default;      同上
Case12  operator= 拷贝 = default;        赋值不是构造 → 默认构造还在 → POD
Case13  operator= 移动 = default;        赋值不是构造 → 默认构造还在 → POD
Case14  ~T() = default;                  析构不是构造 → 默认构造还在 → POD
```

`result.txt` 里 Case10 / 11 第一行就是「默认构造函数: 是否存在: false」，POD 跟着是 false。Case9 默认构造存在且平凡，POD 是 true。

`Case9() = default` 是在 **把默认构造明确给出来**，空类上它仍平凡，六个特殊成员都在，所以和什么都不写（Case1）一样还是 POD。

拷贝/移动赋值、析构即使 `= default` 也不影响「有没有默认构造」，所以 Case12 / 13 / 14 仍可以是 POD。Case13 拷贝被 delete 了，但还有平凡默认构造 + 平凡移动赋值 + 平凡析构，`is_trivial` 仍为 true。

## POD 和聚合：不是一回事

本实验里标准布局全程为 true，所以 **POD ≡ trivial**。聚合走的是另一套规则，问的是「能不能用花括号按成员初始化」，不是「能不能 memcpy」。

| | 聚合 aggregate | POD（C++11 起 ≈ trivial + 标准布局） |
|--|--|--|
| 问的是 | 初始化语法 | 内存表示 |
| 典型能力 | `T t{1, 2};`、C++20 `T t{.x = 1};` | `memcpy`、和 C 结构体按位兼容、`fwrite` 整块写出 |
| 关键限制 | 不能有用户**提供**的构造函数（C++17）；C++20 起不能有用户**声明**的构造函数。可以有用户提供的析构、赋值（C++17） | 必须有平凡默认构造，且拷贝/移动/析构凡是没被 delete 的都必须平凡 |
| C++20 | `is_aggregate` 仍在 | `is_pod` 已弃用，改看 `is_trivial` + `is_standard_layout`，或只为 memcpy 看 `is_trivially_copyable` |

本文件里两者拆开的 Case：

```text
聚合 Y、POD N  →  Case6/7/8/10/11
  可以花括号初始化（C++17），但不能当原始字节块拷
聚合 N、POD N  →  Case2/3/4/5
  有用户提供的构造函数，两种都不是
聚合 Y、POD Y  →  Case1/9/12/13/14/15
  空类、= default，或 default 默认构造再 delete 拷贝（Case15）
```

**什么时候在意聚合**

- 写配置、坐标、纯数据袋：希望 `Color c{255, 0, 0};` 或 `Color c{.r = 255};`，不要再手写一堆构造函数。
- 给 C 风格 API 填结构体、指定初始化字段。
- 不要求能 `memcpy`；成员可以是 `std::string`（有非平凡构造的成员会让整个类既不是 trivial 也不是 POD，但在规则允许时仍可以是聚合——本实验是空类，看不到这一条）。

**什么时候在意 POD / trivial**

- 和 C 互操作、共享内存、网络 buffer：按位复制必须合法。
- `memcpy` / `memmove` 整对象；序列化时当字节块。
- 编译器可以把拷贝优化成按位搬（trivial copy）。
- 只要「按位复制」而不需要默认构造，看 `is_trivially_copyable` 就够（Case10 没有默认构造，不是 POD，但拷贝构造是平凡的）。真正的 C 结构体兼容仍然两者都要：有默认构造、布局也和 C 一样。

**选用**

- 只要花括号初始化 → 保聚合即可，不必强求 POD。
- 要当字节块搬、过 ABI → 要 trivial / 标准布局；最省事是什么特殊成员都不手写（Case1），或只 `= default` 默认构造/赋值/析构（Case9 / 12 / 14）。
- 不要为了「好看」去 `= default` 拷贝/移动构造：C++17 里还是聚合，但已经不是 POD（Case10 / 11）。
- 禁止拷贝但保留 `() = default`（Case15）：C++17 下聚合和 POD 都还在；缺的是拷贝能力，不是「能不能按位表示」。

## 实用结论

1. **只声明移动（Case5 / 11）会砍掉拷贝**；只声明拷贝（Case4 / 10）不会真合成移动，trait 却可能显示「能移动」（其实是拷贝）。
2. **手写空析构（Case8）会让「平凡构造」变 false**，即使默认构造仍是编译器生成的；要保持 POD，写 `= default`（Case14）或不写。
3. **想保持 POD / trivial：要么什么都不写，要么 `= default`。** 写一对 `{}` 就会把 trivial 弄掉，聚合也往往没了。
4. **`= default` 的拷贝/移动构造仍会弄丢 POD**，因为它们是构造函数，会抑制隐式默认构造；`= default` 的默认构造、赋值、析构则不会。
5. **聚合管初始化写法，POD 管按位复制。** 聚合不是 POD 的子集：Case6/7/8/10/11 是聚合但不是 POD。要 `T t{...}` 保聚合；要 `memcpy` / 过 C ABI 保 trivial + 标准布局。
6. **默认构造对 POD 和聚合的影响不一样。** POD 必须有平凡默认构造；C++17 聚合只看有没有用户提供的构造函数。Case10 无默认构造仍是聚合、不是 POD；Case15 有 `() = default` 并 delete 拷贝，两者都还在。Case2 手写 `() {}` 则两个都不是。
